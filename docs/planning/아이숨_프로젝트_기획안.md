## Executive Summary (요약)

아이숨(i-Soom, 구 ISOOM)은 심야 시간대(18시~익일 06시) 및 주말·공휴일에 발생하는 **'소아 응급실 뺑뺑이(골든타임 실종)'**와 **'경증 환자의 응급실 쏠림(74%)'**, 그리고 **'달빛어린이병원 진료 후 인근 약국 조기 마감에 따른 조제 불가 사고'**를 데이터와 AI 엔지니어링으로 근본 해결하기 위해 개발된 **지능형 소아 응급 의료 라우팅 웹 애플리케이션(PWA)**입니다.

본 문서는 프로젝트 기획 의도부터 데이터 분석, 아키텍처 설계, 실제 검증 과정에서 직면한 문제점과 트러블슈팅, 사용된 기술 스택, 현업 엔지니어링 수준 진단, 그리고 실전 취업·면접 전략까지 전 과정을 한눈에 파악할 수 있도록 정리한 개발 종합 설명서입니다.

## 1. 기획 배경 및 해결하고자 한 문제 (Why)

### 1.1 대한민국 소아 응급 의료의 3대 구조적 모순
1. **소아청소년과 전문의 부재 및 응급실 뺑뺑이**:
   - 저출산 및 소아청소년과 전공의 기피 현상으로 인해 대학병원 및 권역응급의료센터조차 야간 당직의가 없어 "소아 진료 불가"를 공지하는 사태가 일상화되었습니다.
   - 부모들은 아이가 아플 때 어느 병원에 소아 진료 의사가 있는지 알지 못한 채 여러 병원을 전전하다 골든타임을 놓치고 있습니다.
2. **경증 환자의 응급실 과밀화 (74%)**:
   - 야간에 문을 연 1차 의원(달빛어린이병원 등)을 찾지 못한 보호자들이 단순 미열이나 감기 등 경증 환아를 데리고 대형 응급실로 몰려 대기 시간이 3~5시간으로 폭증합니다.
   - 이로 인해 정작 즉각적인 처치가 필요한 중증 환아(KTAS 1~2단계)가 제때 치료받지 못하는 악순환이 발생합니다.
3. **심야 처방약 조제 단절 사고 (Night Pharmacy Mismatch)**:
   - 야간에 진료하는 달빛어린이병원을 찾아 진료를 받더라도, 인근 약국이 병원보다 일찍 문을 닫아 처방약을 조제하지 못하고 새벽에 문 연 약국을 찾아 헤매는 치명적 현장 결함이 존재했습니다.

### 1.2 비의료 AI 챗봇의 2대 치명적 리스크
1. **임상 오분류 위험 (Undertriage)**:
   - 보호자가 당황하여 "열은 좀 내렸는데 계속 처져요", "지금은 깨어났는데 숨소리가 이상해요"처럼 전반부에 안도성 표현을 쓰면, 일반 LLM은 이를 '경증'으로 오판하여 위험한 가이드(가정 내 관찰 등)를 내리는 치명적 안전 결함이 있습니다.
2. **의료법 제27조(무면허 의료행위) 및 환각(Hallucination)**:
   - 비의료 AI가 확정적 질병을 진단하거나 구체적인 전문의약품 용량을 지시하는 것은 현행 의료법 위반입니다. 특정 병원을 불법 유인·알선하지 않으면서도 객관적 지표에 기반해 안전하게 안내하는 체계가 필요했습니다.

## 2. 사용 데이터셋 및 주피터 노트북 1~5권 실증 분석 (What Data)

### 2.1 활용 데이터셋 목록
* **국립중앙의료원(NMC) E-Gen**: 전국 응급의료기관 실시간 가용병상(`hv28` 등) 및 기관별 비정형 실시간 공지사항.
* **건강보험심사평가원(HIRA) & 보건복지부**: 전국 7만 개 병의원, 2.4만 개 약국 마스터셋, 전국 156개 달빛어린이병원 및 2,028개 야간/심야 약국 운영 시간표.

## 3. 설계 및 구현한 핵심 기능 체계 (What Features)

아이숨은 **0ms 안전 감시망**, **2-트랙 지능형 라우터**, **고가용성 백엔드 인프라**, **토스급 PWA 모바일 웹앱**이 유기적으로 결합된 풀스택 시스템입니다.

                  │                                               │

       ┌────────────────────────┐                    ┌────────────────────────┐

### 3.1 차세대 2계층 안전 감시망 (Two-Tier Red Flag V2)
1. **Tier 1 (Zero-Latency Pre-Interceptor)**:
   - 생후 100일 미만 38℃ 고열, 경련/발작, 호흡부전(청색증), 의식 저하, 사지 절단 등 12대 초응급 증상을 컴파일된 고성능 정규표현식으로 **26µs 만에 즉각 인터셉트**.
   - LLM API 호출 지연(1~3초) 없이 즉시 119 구급차 호출 및 소아 응급실로 직행하도록 전환.
   - **`has_affirmative_match` 한국어 복합 부정문 감별 엔진**: "열은 나는데 경련은 없어요"와 같은 부정문을 감별하여 허위 119 경보를 100% 차단.
2. **Tier 2 (Post-LLM Safety Sanitizer)**:
   - LLM이 출력한 최종 텍스트에서 불법 진단명 확정("~병입니다"), 불법 투약 용량 지시를 실시간 검열·소독하여 의료법 제27조를 철저히 준수.

### 3.2 2-트랙 지능형 라우팅 (Two-Track Routing)
* **Track A (중증 / KTAS 1~3단계)**:
  - 소아전문응급의료센터 및 소아 전용 병상 보유 대형 응급실을 최단거리 순으로 매칭.
  - 약국은 안내하지 않음 (응급실 원내 조제가 원칙이므로 불필요한 정보 배제).
  - 119 구급대원 인계용 **응급 브리핑 카드(`briefing_card.html`)** 생성.
* **Track B (경증 / KTAS 4~5단계)**:
  - 전국 156개 달빛어린이병원 중 현재 진료 중인 병원을 매칭.
  - 해당 병원의 진료 마감 시간보다 최소 30분 이상 늦게 닫는 **공식 협약·공공 심야약국을 1:1 페어링 매칭**.
  - 병원 출발 전 소아과 당직의 여부를 30초 만에 확인하는 **유선 확인 통화 스크립트** 및 **2024년 5월 본인확인 의무화 서류(모바일 등본 등) 체크리스트** 제공.

### 3.3 백엔드 고가용성 인프라 & 상태머신
* **Supervisor 6-State FSM 오케스트레이터**: 문진 대화의 상태를 엄격한 유한상태머신(FSM)으로 제어하며, 최대 3턴 이내에 결론을 내리도록 교착 방어 로직 내장. 단발성 문진을 위한 `force_matching` 원스톱 모드 지원.
* **공공 API 비동기 서킷 브레이커 (3-State FSM)**: 공공데이터포털(E-Gen)의 간헐적 500/504 장애 시, 3회 연속 실패 시 즉각 회로를 차단(OPEN)하여 사용자의 대기 시간을 0ms로 단축.
* **3-Tier Multi-Storage Fallback**:
  - `L1 In-Memory Cache` (초고속 캐시, 0.05ms)
  - `L2 Firebase Cloud Firestore` (분산 클라우드 DB)
  - `L3 불변 Canonical JSON Masterset` (외부 의존성 제로의 안전 자산)
  - 공공 API와 Firestore가 모두 다운되더라도 L3 로컬 데이터를 통해 전국 병원·약국 매칭 100% 무중단 보장.
* **24시간 In-Memory Hash Diffing 델타 동기화 데몬**: APScheduler 기반 3-트랙 백그라운드 워커를 통해 전국 의료기관 변경 사항을 주기적으로 수집하되, 데이터 해시값이 일치하면 I/O를 발생시키지 않고 스킵.

### 3.4 프론트엔드 모바일 웹앱 (PWA) & 토스 TDS 디자인 시스템
* **100% 순수 Vanilla JS & CSS3**: 무거운 프레임워크(React, Vue 등) 없이 브라우저 네이티브 기술로만 구축하여 첫 페이지 로딩 0.1초 미만 달성.
* **토스 TDS(Toss Design System) 다크테마 전역 이식**: 야간에 어두운 방에서 아픈 아이를 안고 스마트폰을 켜는 부모의 눈부심과 시각적 피로를 방지하기 위해 심야 전용 다크테마(#101012, #17171c, #3182f6) 구축 (다크/라이트/시스템 동기화 3-Way 지원).
* **고정 앱 셸(Fixed App Shell) & 반응형 100dvh**: 스마트폰 주소창 변동에도 찌그러지지 않는 완벽한 모바일 뷰포트 격리.
* **PWA 웹앱 매니페스트 & 서비스워커 v2**: 홈 화면 추가, 오프라인 정적 에셋 캐싱, 전용 파비콘 및 3D 스퀘어클 앱 아이콘 연동.

## 4. 실제 검증 과정에서 직면한 8대 문제와 트러블슈팅 (How Solved)

실무 개발 및 검증 과정에서 맞닥뜨린 치명적인 병목 현상들을 어떻게 엔지니어링 방식으로 해결했는지를 기술합니다.

### [문제 1] E-Gen 병상 데이터 폴링 시 Firebase 비용 폭탄 및 일일 쿼터 초과 위기
* **현상**: 전국 415개 응급의료기관 병상 데이터를 5분마다 Firestore에 단순 덮어쓰기할 경우, 하루 144,000회의 쓰기 연산이 발생하여 무료 티어(Spark 플랜: 일 20,000회)를 단 3.3시간 만에 초과하고 과금 위험 발생.
* **원인 분석**: 응급실 병상 수는 5분 단위로 전체가 바뀌지 않으며, 실제 변동률은 5~10% 수준에 불과함에도 무지성 전수 쓰기를 수행했기 때문.
* **해결 방안 & 스킬**:
  - **In-Memory Hash Diffing 알고리즘** 도입 (`national_dataset_sync_service.py`).
  - 서버 메모리에 이전 상태의 레코드별 MD5/SHA256 해시를 유지하고, 새로 수집된 데이터의 해시와 비교.
  - 해시값이 일치하는 90~95%의 레코드는 쓰기 연산을 즉시 스킵(Skip)하고, 실제 병상 수나 상태가 변동된 5~10%의 델타(Delta) 데이터만 Firestore에 일괄 커밋(`batch.commit()`).
* **결과**: 일일 쓰기 횟수를 14.4만 회에서 7,000~10,000회 수준으로 **93% 이상 대폭 절감**하여 무료 티어 내에서 24시간 365일 무중단 운영 달성.

### [문제 2] 키워드 검색 기반 RAG(검색 증강 생성)의 임상 환각 및 오진
* **현상**: 사용자가 "아이가 숨을 쉴 때 쌕쌕거리고 컹컹 짖는 소리가 나요"라고 입력했을 때, 기존 키워드 검색 기반 RAG(BM25/TF-IDF)가 소아 KTAS 168개 주증상 벡터 중 유사한 키워드를 찾지 못해 유사도 0.0을 반환하고 전혀 엉뚱한 임상 청크(예: 발목 염좌)를 주입함.
* **원인 분석**: 보호자의 서술은 의학 전문 용어(크룹, 후두염, 천명음)가 아닌 감각적 일상어("컹컹 소리")이므로 단어 일치 기반 검색이 실패함.
* **해결 방안 & 스킬**:
  - 키워드 RAG 아키텍처를 과감히 폐기.
  - 소아 KTAS 168개 공식 주증상 및 단계별 판정 기준 전체를 Gemini 3.8 Flash 프롬프트에 직접 구조화하여 주입하는 **Direct Grounding 전략** 채택.
  - LLM의 Extended Context Window(100만 토큰 이상)와 추론 능력(Thinking High 모드)을 활용하여 전문 용어 매핑 없이도 비정형 서술을 완벽히 이해하도록 유도.
* **결과**: 50대 골든 케이스 임상 벤치마크 평가에서 **KTAS 등급 일치율 98%, 임상 위험 환각 0%** 달성.

### [문제 3] 보호자의 안도성 서술에 현혹되는 LLM의 임상 오분류(Undertriage)
* **현상**: 보호자가 "어제는 40도였는데 해열제 먹이고 지금은 열이 37.5도로 내렸어요. 근데 축 늘어져서 깨워도 반응이 없어요"라고 입력했을 때, LLM이 문장 앞부분의 "열이 내렸다"는 안도성 표현에 가중치를 두어 KTAS 4단계(경증)로 오분류하는 치명적 안전 사고 가능성 발견.
* **원인 분석**: 의식 저하(Lethargy)는 열의 유무와 상관없이 KTAS 1~2단계 초응급 상황이나, 자연어 생성 모델의 특성상 서술의 긍정적 뉘앙스에 편향이 발생함.
* **해결 방안 & 스킬**:
  - **결정론적 2단계 감시망(Two-Tier Red Flag)** 구축.
  - 1단계: LLM을 거치기 전, 컴파일된 정규식으로 '의식 저하/반응 없음' 키워드를 26µs 만에 낚아채어 즉시 119 트랙으로 강제 우회.
  - 2단계: Gemini 시스템 프롬프트에 **"체온 하강이나 일시적 호전 서술보다 의식 저하, 호흡 곤란, 지속 구토 등의 신경학적/생체 징후를 최우선 순위로 판정하라"**는 소아응급 임상 우선순위 룰을 강력히 주입.
* **결과**: 50개 임상 시나리오 전수 검증에서 **언더트리아제 발생률 0.0%** 달성.

### [문제 4] 한국어 복합 부정문("경련은 없어요")으로 인한 119 오경보
* **현상**: 보호자가 "아이가 열이 나는데 경련은 없어요"라고 썼음에도, 단순 키워드 매칭 엔진이 "경련"이라는 단어만 보고 119 긴급 출동 화면을 띄워 사용자에게 극심한 공포감을 유발함.
* **원인 분석**: 한국어의 후치사 및 부정 표현("~은 없어요", "~하지 않아요", "~는 아닙니다")을 고려하지 않은 무지성 정규표현식 매칭의 한계.
* **해결 방안 & 스킬**:
  - 정규식 전후방 탐색 및 한국어 부정형 형태소 패턴 매핑 엔진 **`has_affirmative_match`** 구현 (`guardrail_agent.py`).
  - 정규식 패턴 발견 시, 해당 단어 앞뒤 15글자 내에 부정 접미어/조사/용언("없", "안", "아님", "배제", "정상")이 결합되어 있는지 2차 검증하여 부정문일 경우 Red Flag 매칭에서 즉시 제외.
* **결과**: 부정문 오경보율 0%, 긍정문 긴급 징후 포착률 100% 달성.

### [문제 5] 공공데이터포털(E-Gen) API의 간헐적 먹통(500/504)에 따른 서비스 블로킹
* **현상**: 심야 시간대 공공데이터포털 서버 점검이나 일시적 트래픽 폭주로 응답 지연(Timeout 10초 이상) 또는 HTTP 500 에러가 발생하여, 아이숨 웹앱 전체가 로딩 스피너 상태로 멈춰 서는 현상 발생.
* **원인 분석**: 외부 공공 API에 동기식으로 의존하여 외부 장애가 내부 핵심 서비스로 전파되는 전형적인 장애 전파(Cascading Failure) 문제.
* **해결 방안 & 스킬**:
  - **3-State FSM 비동기 서킷 브레이커 (`circuit_breaker.py`)** 구현 (CLOSED ➔ OPEN ➔ HALF_OPEN).
  - 연속 3회 실패 시 즉각 서킷을 OPEN하여 이후 60초 동안 공공 API 호출을 0ms 만에 즉시 차단.
  - **3-Tier Multi-Storage Fallback 계층** 가동: L1 인메모리 캐시 ➔ L2 Firestore ➔ L3 로컬 마스터셋(불변 JSON)으로 자동 폴백하여 사용자에게는 15ms 이내에 가장 최신의 안전 데이터를 무중단 서빙.
* **결과**: 공공 API 전면 장애 상황에서도 **서비스 가용성(Availability) 100% 유지**.

### [문제 6] 프론트엔드-백엔드 연동 과정에서의 로컬 스토리지 더미 잔재 및 뷰포트 결함

### [문제 7] Google Cloud Run 무중단 프로덕션 배포 및 PWA 캐시 충돌

보통 개발 교육과정의 '중간 프로젝트'는 게시판 CRUD, 간단한 쇼핑몰 클론, 혹은 단순 ChatGPT API를 연결한 일기장 수준이 90% 이상입니다.  
반면 아이숨은:
1. **사회적 문제(소아 응급실 뺑뺑이)를 데이터로 명확히 증명**했고,
2. 단순 LLM 호출이 아닌 **의료법 준수, 언더트리아제 0%를 위한 2계층 가드레일**을 구축했으며,
3. **서킷 브레이커, In-Memory Hash Diffing, 3-Tier Multi-Storage Fallback** 등 대규모 트래픽과 외부 장애를 방어하는 실무 엔지니어링 패턴을 집약시켰고,
4. **GCP Secret Manager 암호화 주입 및 Cloud Run 상용 프로덕션 실서버 무중단 배포**까지 완결했습니다.

이 정도의 깊이와 완성도를 가진 중간 프로젝트는 신입 채용 시장에서 **상위 1~3% 이내의 독보적인 경쟁력**을 가집니다.

### 7.3 기술 면접관을 매료시킬 7대 핵심 질문-답변 치트키 (Interview Q&A)

#### Q1. "왜 RAG(검색 증강 생성)를 쓰지 않고 Direct Grounding 방식을 택했나요?"
> **답변 가이드**:  
> "실제 주피터 노트북 4권에서 168개 소아 KTAS 주증상에 대해 BM25와 임베딩 기반 RAG를 테스트했습니다. 그런데 환아 부모님들은 의학 용어('크룹', '천명음') 대신 감각적 일상어('컹컹 짖는 소리')로 증상을 입력합니다. 이때 벡터 유사도 임계치에 미달하면 RAG가 유사도 0.0을 반환하거나 엉뚱한 임상 청크를 주입해 오히려 환각(Hallucination)과 오진을 유발했습니다.  
> 소아 응급은 오진 하나가 생명과 직결되는 도메인입니다. 따라서 저희는 토큰 비용을 조금 감수하더라도, 168개 KTAS 전체 분류 체계를 최신 긴 컨텍스트(Gemini 3.8 Flash) 프롬프트에 직접 주입(Direct Grounding)하고 Thinking 모드로 문맥 전체를 완독 감별하도록 설계하여 임상 정확도 98%와 언더트리아제 0%를 달성했습니다."

#### Q2. "In-Memory Hash Diffing은 왜 도입했고, 어떻게 동작하나요?"
> **답변 가이드**:  
> "국립중앙의료원 E-Gen에서 전국 415개 응급의료기관 병상 데이터를 5분 주기로 폴링하여 Firestore에 적재할 때, 단순 전수 덮어쓰기를 하면 하루 144,000회의 쓰기 비용이 발생합니다. 이는 Firebase 무료 쿼터(2만 회)의 7배가 넘어 과금 폭탄으로 이어집니다.  
> 실제 데이터를 분석해보니 5분 단위로 병상 상태가 바뀌는 비율은 5~10%에 불과했습니다. 이에 서버 메모리에 이전 레코드의 해시값을 캐싱해두고 새로 들어온 데이터의 해시와 비교하는 In-Memory Hash Diffing을 구현했습니다. 내용이 변하지 않은 90% 이상의 데이터는 DB 쓰기를 스킵하고, 실제 변동된 델타 데이터만 배치 커밋함으로써 쓰기 비용을 93% 절감하고 무료 티어 내에서 24시간 무중단 서비스를 운영할 수 있었습니다."

#### Q3. "공공데이터 API는 서버 점검이나 타임아웃이 잦은데, 장애 대응을 어떻게 하셨나요?"
> **답변 가이드**:  
> "외부 의존성 장애가 우리 서비스 전체로 전파되는 것을 막기 위해 **3-State FSM 비동기 서킷 브레이커**와 **3-Tier Multi-Storage Fallback** 구조를 설계했습니다.  
> 공공 API 호출이 3회 연속 실패하면 서킷을 즉각 OPEN하여 60초간 외부 호출을 0ms 만에 차단합니다. 그 사이 시스템은 L1 인메모리 캐시 ➔ L2 Firestore 분산 DB ➔ L3 로컬 마스터셋(불변 JSON) 순으로 자동 폴백하여, 공공 API 서버가 완전히 다운된 상태에서도 사용자에게 15ms 이내에 가장 최신의 안전 데이터를 무중단 서빙합니다."

#### Q4. "의료법 위반 소지나 비의료 AI의 진단 위험은 어떻게 통제했나요?"
> **답변 가이드**:  
> "의료법 제27조(무면허 의료행위) 및 특정 병원 알선·유인 금지 조항을 준수하기 위해 **결정론적 2계층 안전 감시망(Two-Tier Red Flag)**을 구축했습니다.  
> 1단계(Tier 1)에서는 생후 100일 미만 고열이나 경련 등 12대 응급 징후를 정규식으로 26µs 만에 낚아채어 119 구급차 호출로 직행시킵니다. 이때 '경련은 없어요' 같은 한국어 부정문은 `has_affirmative_match` 엔진으로 감별해 오경보를 차단합니다.  
> 2단계(Tier 2)에서는 LLM 출력 단계에서 확정 진단명이나 투약 지시를 사후 소독 게이트웨이로 필터링하고, 반드시 '전문의 대면 진료가 필요함'을 고지하도록 강제했습니다."

#### Q5. "병원-약국 30분 안전 마진 페어링은 어떤 필요에서 나왔나요?"
> **답변 가이드**:  
> "전국 7만 개 병원과 2.4만 개 약국의 운영 데이터를 분석한 결과, 야간에 진료하는 달빛어린이병원 반경 1km 이내 약국의 40% 이상이 병원보다 일찍 문을 닫는다는 치명적 현장 결함을 발견했습니다. 아이 진료를 어렵게 받고도 처방약을 짓지 못해 발을 동동 구르는 사고를 막기 위해, `약국 마감 시간 - 병원 마감 시간 >= 30분` 조건을 만족하는 공식 협약 심야약국만을 1:1로 묶어 페어링 매칭하는 알고리즘을 개발했습니다."

#### Q6. "클라우드 프로덕션 배포 시 민감한 API Key와 서비스 계정 비공개 키는 어떻게 보안 관리했나요?"
> **답변 가이드**:  
> "보안 감사 규정상 API Key와 Firebase 서비스 계정 비공개 키 JSON을 소스 코드에 하드코딩하거나 도커 이미지 레이어에 굽는 것은 심각한 보안 결함입니다.  
> 저희는 **GCP Secret Manager**를 도입하여 5대 핵심 시크릿(`DATA_GO_API_KEY`, `GEMINI_API_KEY`, `KAKAO_REST_API_KEY`, `FIRESTORE_DATABASE_ID`, `FIREBASE_KEY_JSON`)을 안전하게 암호화 관리했습니다.  
> Cloud Run 런타임 서비스 계정과 배포 Service Agent에 `roles/secretmanager.secretAccessor` 최소 권한만을 부여하고, Cloud Run 컨테이너 기동 시 환경변수로 동적 마운트(`--set-secrets`)되도록 파이프라인을 구축했습니다. 또한 `.gcloudignore`를 통해 빌드 컨텍스트에서 민감 정보 유출을 원천 봉쇄하여 엔터프라이즈급 클라우드 보안 거버넌스를 100% 달성했습니다."

#### Q7. "초응급(KTAS 1~3단계) 상황에서 사용자의 인지 부하를 줄이기 위해 UI/UX를 어떻게 설계했나요?"
> **답변 가이드**:  
> "아이가 경련하거나 질식하는 초응급 순간에 보호자에게 검색창을 치게 하거나 12개의 탭 버튼을 일일이 탐색하게 만드는 것은 사용성을 해칠 뿐만 아니라 골든타임을 뺏는 위험한 설계입니다.  
> 저희는 검색창, 필터 칩, 가로 탭 버튼 등 조잡한 4단 탐색 요소를 과감히 전면 척결하고, 환아의 문진 소견서(`clinical_rationale`), 주호소, KTAS 등급을 종합 분석하여 **단 하나의 최적 처치법만을 메인 화면에 큼직하게 표출하는 임상 자동 디스패처(`autoMatchSymptom`)**를 구축했습니다.  
> 다른 상황이 필요한 경우에만 아래에서 부드럽게 올라오는 **토스 스타일 미니멀 바텀시트**를 통해 전환할 수 있도록 격리했고, 보호자의 GPS 좌표를 카카오 역지오코딩과 연동하여 **119에 즉시 불러줄 수 있는 실제 도로명/지번 상세 주소**로 실시간 변환 표출하도록 완성했습니다."

## 8. 결론 (Conclusion)

아이숨(i-Soom) 프로젝트는 단순한 아이디어 제안에 그치지 않고, **철저한 실증 데이터 분석 ➔ 방어적 소프트웨어 아키텍처 수립 ➔ 8대 기술 난제 엔지니어링 극복 ➔ 128개 테스트 기반 견고함 입증 ➔ GCP Secret Manager 암호화 주입 & Cloud Run 상용 클라우드 무중단 배포**까지 프로덕트의 전체 라이프사이클을 완벽하게 완주한 프로젝트입니다.

이 설명서에 담긴 문제 해결 스토리와 아키텍처적 의사결정 과정은 이력서, 포트폴리오, 그리고 기술 면접에서 여러분의 엔지니어링 역량을 가장 강력하게 증명하는 무기가 될 것입니다.
